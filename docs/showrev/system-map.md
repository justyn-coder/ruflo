# ShowRev System Map

## Destinations — What Lives Where

| Location | What it is | What lives there | Who sees it |
|----------|-----------|------------------|-------------|
| `~/Documents/GitHub/ruflo` | **Engine repo** (local). Pipeline source code, email finder, personas, composer, judge, brain. | All pipeline TypeScript (`src/showrev/`), brain data (`data/brain/`), telemetry (`data/showrev/premium/telemetry/`), pipeline .env (`src/showrev/m1-email-find/.env`) | Developer only |
| `github.com/ruvnet/ruflo` | **GitHub remote** for the engine repo. Also hosts the claude-flow framework. | Same as above once pushed. ShowRev is a consumer of claude-flow that lives inside the same repo at `src/showrev/`. | Public (OSS framework), private (showrev engine code in same tree) |
| `showrev-microsites.vercel.app` | **Ops portal** (Mission Control). Where Tim and Justyn review pipeline output. | Next.js app. Reads from `sr_prospects`, `sr_engine_output`, `sr_microsites`, `sr_review_notes` in Supabase. Source: `~/Documents/GitHub/showrev-microsites/` | Tim (reviewer), Justyn (operator) |
| `fiber.inorsa.com` | **Production microsite domain**. Personalized prospect briefs live here. | Static brief pages at `/brief/{slug}`. Content generated by pipeline Phase 8, deployed via the microsites repo. Prospects see this URL in email P.S. | Prospects (external) |
| `~/Documents/GitHub/showrev-microsites` | **Microsites source repo** (local). The deployed Vercel app. | Next.js pages, Supabase queries, OpsTable, ExpandedView, NotesPanel. This is what deploys to both `showrev-microsites.vercel.app` (ops) and `fiber.inorsa.com` (prospect-facing). | Developer only |

## Data Flow

```
CSV input
  → ruflo pipeline (src/showrev/m1-email-find/run-pipeline.ts)
    → writes to Supabase (sr_prospects, sr_engine_output, sr_microsites)
      → showrev-microsites reads from Supabase
        → Ops portal: showrev-microsites.vercel.app/ops
        → Prospect briefs: fiber.inorsa.com/brief/{slug}
```

## Environment / Keys

All pipeline API keys live in: **`src/showrev/m1-email-find/.env`** (19 vars).
The pipeline auto-loads this file via dotenv regardless of CWD (fixed 2026-06-07).

| Key | Service | Required? |
|-----|---------|-----------|
| ANTHROPIC_API_KEY | Research + composition + judge LLM calls | Yes |
| SUPABASE_SERVICE_ROLE_KEY | Read/write sr_* tables | Yes |
| NEXT_PUBLIC_SUPABASE_URL | Supabase project URL | Yes |
| NEXT_PUBLIC_SUPABASE_ANON_KEY | Supabase anon key (fallback) | Yes |
| APOLLO_API_KEY | Apollo People Match (email fallback) | Recommended |
| MILLIONVERIFIER_API_KEY | Email deliverability check | Optional (currently missing) |
| GEMINI_API_KEY | Cross-model judge | Optional |
| OPENAI_API_KEY | Cross-model judge | Optional |
| XAI_API_KEY | Cross-model judge (Grok) | Optional |
| DEEPSEEK_API_KEY | Cross-model judge | Optional |

## What NOT to confuse

| Wrong | Right |
|-------|-------|
| Edit `ruflo/src/showrev/microsite/` for portal changes | Edit `~/Documents/GitHub/showrev-microsites/` — that's the deployed repo |
| Source `.env` manually before pipeline runs | Pipeline auto-loads its own .env (fixed 2026-06-07) |
| Push showrev engine code to showrev-microsites | Engine lives in ruflo. Microsites is frontend only. |
| Look for API keys in root `.env` | Keys are in `src/showrev/m1-email-find/.env` |
