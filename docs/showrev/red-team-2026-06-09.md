# Section 5: Conflicts / contradictions / hallucinations

1. **CRITICAL — Persona detector split brain.** `influence.ts:74` (two-token regex pair, extended 2026-06-09 to include AI/innovation/data/platform) vs `generalized-composer.ts:87` (simple one-token regex). `run-pipeline-v2.ts:616` uses canonical; `specific-composer.ts:55,267` and `generalized-composer.ts:315` use the simple version. **Result: composer can bucket "Director of Construction" or "Head of AI & Innovation" into a different persona than the persisted `persona_bucket` field and than the microsite composer (which uses `influence.detectPersona` at line 825).** Recommendation: delete `detectPersona` from `generalized-composer.ts`, re-export from `influence.ts`. Severity: **critical** (wrong pitch variant + wrong PS variant on every borderline title).

2. **CRITICAL — Word-count unit disagreement.** SoT §11: T1/T2 body ≤80w (88w flex), T3 ≤60w. Composers: body+P.S. (URL excluded) ≤100w. Tiered judge: body alone ≤100w. Three units, three numbers. Recommendation: align on SoT (≤80w body). Severity: **critical** (every composed email is potentially 20w over the documented rule).

3. **CRITICAL — Em-dash leak in microsite.** Composers post-process em-dashes to commas. `microsite-composer.ts` does not. SoT §11 bans em-dashes in prospect-facing copy. Microsite IS prospect-facing. Recommendation: add the same `.replace(/[—–]/g, ',')` post-process to microsite output. Severity: **critical** (Tim explicitly flagged em-dashes as AE-LARP tell — visible to prospects on the landing page).

4. **CRITICAL — `send_status` write inconsistency between `sr_engine_output` and `sr_prospects`.** Line 666 uses `sendStatusForOutput` (system_brief flag only). Line 734 uses `result.send_status || (flag_status ? 'flag' : sendStatusForOutput)` (tiered-judge flag honored). Operator portal reads `sr_prospects`. A red-confidence email with tiered-judge flag will show `flag` on `sr_prospects` and `pending` on `sr_engine_output` — or vice-versa depending on which signal fires. Recommendation: compute a single `finalSendStatus` once, write to both. Severity: **critical** (operator sees different statuses on the same prospect depending on view).

5. **MEDIUM — `MILLIONVERIFIER_API_KEY` missing = silent no-op.** `million-verifier.ts:37` returns `quality:'unknown'` if no key. The orchestrator treats `'unknown'` as "no signal, keep yellow/red." Result: a missing-env cohort runs as if MV was never wired — the entire 0aa9f2d01 commit's promised lift evaporates with zero alert. Recommendation: fail fast if any `millionVerifierFn` is provided but `MILLIONVERIFIER_API_KEY` is missing; OR log a single bold warning at pipeline start. Severity: **medium** (correctness depends on operator catching the silent failure).

6. **MEDIUM — Pitch verbatim quadruplicated.** `influence.ts`, `generalized-composer.ts`, `specific-composer.ts`, `test-quality-checker.ts`. If a Nick correction tweaks variant B by one word, three of four must be updated by hand. Recommendation: import from one canonical export. Severity: **medium**.

7. **MEDIUM — ICP CTA library duplicated.** `influence.ts:362` and `composer-constraints.ts:129`. Currently identical. Same drift risk as above. Severity: **medium**.

8. **MEDIUM — Apollo + MV credit budgets asymmetric.** Apollo has `ApolloCreditTracker` + `--max-apollo-credits` CLI flag. MV has no equivalent. A 300-prospect run can fire MV up to ~1200 times (Path A red fallback × 3 hooks). Recommendation: add `MvCreditTracker` + `--max-mv-credits` mirror. Severity: **medium**.

9. **MEDIUM — Microsite composer JSON.parse crash.** Line 162 throws on malformed model output with no retry. Any single JSON-parse failure burns one LLM call and falls all the way through to templated. Composers (specific/generalized) wrap parse in retries. Recommendation: mirror the parse-with-retry pattern. Severity: medium.

10. **MEDIUM — `microsite-composer.ts:174` headline anti-company check is fragile.** Uses `prospect.company.toLowerCase().slice(0, Math.min(8, prospect.company.length))` and `includes()` — collisions with short common substrings ("Citizens", "Pioneer") incorrectly flag legitimate headlines. Severity: medium (may force retry storms on common-name companies).

11. **MEDIUM — Supabase fetches have no timeouts in `run-pipeline-v2.ts` (lines 690, 742, 882, 961) or `peer-pattern.ts` (line 165).** Any Supabase stall hangs the pipeline indefinitely. Recommendation: wrap every fetch with `AbortSignal.timeout(15_000)`. Severity: medium.

12. **LOW — `tiered-judge.ts` paragraph rule allows 3-4** while composers force exactly 3 (lines 119, 336, 364). Today this can't fire (composer pre-filters), but if composer is later loosened, the inconsistency surfaces. Severity: low.

13. **LOW — `peer-pattern.ts` returns hard-coded `confidenceValue` numbers (0.95 / 0.7 / 0.4)** that aren't documented anywhere in SoT or specs. If operator later wants to re-tune, these are buried in a literal. Severity: low.

14. **LOW — `apollo-fallback.ts` maps Apollo `email_status === 'guessed'` to `confidence:'low'`** (line 83), while `apollo-client.ts:findEmailForProspect` peer-pattern branch emits `confidence:'guessed'` directly. Two layers, two encodings of the same concept. Severity: low (works today because pipeline only consumes `'guessed'` from peer-pattern, not direct).

15. **LOW — `run-pipeline-v2.ts` accepts both `SUPABASE_SERVICE_ROLE_KEY` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`** (line 583). On a misconfigured environment, falls to anon key which lacks RLS bypass for upserts. Could cause silent partial writes. Severity: low (but high blast-radius if it fires).

16. **LOW — `selectPSVariant` called twice per composer** (in `buildPrompt` to inject into LLM, then again in `composeXxx` to attach to output JSON). Both calls use the same args today. If the prompt-builder is ever called with different args than the persistence path, prompt and persisted PS will silently disagree. Recommendation: select once, pass in. Severity: low.
